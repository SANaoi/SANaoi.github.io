目標

一般的に、3D オブジェクトで使うマテリアル Shader には、いくつかの基本的な要素があります。たとえば UV テクスチャ、法線、光の受け取り、そして影の生成です。

この記事の目標は、まず基礎的な Lit Shader を実装し、今後のエフェクト実装の土台にすることです。

含まれる内容

今回実装する Shader には、主に次の機能が含まれます。

  • UV を使ってテクスチャをサンプリングする
  • 法線マップで表面のディテールを強調する
  • Lambert ライティングモデルでライティング計算を行う
  • ShadowCaster Pass によって物体が影を落とせるようにする

宣言する構造体

ベースカラーと UV サンプリング

最初の部分は比較的分かりやすいです。_BaseMap からテクスチャをサンプリングし、さらに _BaseColor を掛けることで、最終的なベースカラーを得ます。

ここで使っている IN.uv は頂点ステージから渡される値です。頂点シェーダーでは、テクスチャの Tiling と Offset に応じて UV を変換します。

この処理によって、テクスチャがモデル表面にどのように貼られるかが決まります。処理自体は複雑ではありませんが、テクスチャを使うほとんどの表現はここから始まります。

法線マップ

通常のカラーテクスチャは表面の色だけを変えますが、ライティング計算で使う方向そのものは変えません。

法線マップの役割は、各ピクセルに追加の法線方向を持たせることです。これにより、モデル自体のポリゴン数を増やさなくても、ライティング結果で凹凸のディテールを表現できます。

Shader では、まず法線マップをサンプリングし、UnpackNormalScale で展開します。

次の画像を見ると、法線マップの効果をより直感的に理解できます。左側は法線マップを使用していない状態、右側は法線マップを使用した状態です。右側では、光が当たったときに表面の細かい凹凸がよりはっきり見えます。

左側は法線マップなし、右側は法線マップあり。光が当たったとき、表面の凹凸感がより強く表れています。

注意したいのは、法線マップはモデルの形状を実際に変形しているわけではない、という点です。変えているのは、ライティング計算に使われる法線方向です。ここで得られる normalTS は接線空間の法線なので、そのままワールド空間のライティング計算には使えません。先に空間変換が必要になります。

TBN 空間変換

テクスチャサンプリングと法線マップの処理ができたので、次はライティング計算に進みます。ただし、ワールド空間でライティング計算を行うためには、接線空間の法線をワールド空間へ変換する必要があります。そこで使うのが TBN 行列です。

モデルの頂点には通常、法線と接線の情報が含まれています。Unity が提供する GetVertexNormalInputs を使うと、ワールド空間の Normal、Tangent、Bitangent を取得できます。それぞれ法線、接線、副接線を表します。接線と副接線は互いに垂直で、どちらも表面の接平面上にあります。法線、接線、副接線の 3 方向を組み合わせることで、TBN 行列を作ることができます。

頂点シェーダーでは、TBN 行列の 3 行をフラグメントシェーダーへ渡します。

これら 3 つの方向を使うことで、法線マップから得た接線空間の法線をワールド空間へ変換できます。

ライティング計算

ライティング計算は Shader の中でも特に重要な部分です。ここでは Lambert ライティングモデルを使います。Lambert は最も基本的な拡散反射モデルで、粗い表面で光が均等に散乱するような見え方を表現します。基本式は次の通りです。

Cdiffuse = Calbedo · Clight · max(0, N · L)

それぞれの意味は次の通りです。

  • C_diffuse：最終的に計算される拡散反射光の色。
  • C_albedo：材質そのものの色。ここではテクスチャ色に相当します。
  • C_light：入射光の色と強さ。
  • N：表面法線方向。通常は単位ベクトルである必要があります。
  • L：光源方向。こちらも通常は単位ベクトルである必要があります。
  • N · L：法線方向と光源方向の内積で、表面がどれだけ光源を向いているかを表します。

表面が光源を正面から向いているほど、N · L は 1 に近づき、光は強くなります。一方、表面が光源の反対側を向いている場合、N · L は 0 より小さくなります。光の強さが負になることはないので、max(0, N · L) で 0 未満を切り捨てます。Shader では通常、saturate を使って同じ処理を行います。

実際のライティング計算では、影、距離減衰、環境光なども考慮する必要があります。そのため、直接光の計算は次のように拡張できます。

Cdirect = Calbedo · Clight · max(0, N · L) · Adistance · Ashadow

ここで使っている項の意味は次の通りです。

  • A_distance：距離減衰値。通常は 0 ~ 1 の範囲で、光源から遠ざかるほど光が弱くなることを表します。
  • A_shadow：影の減衰値。通常は 0 ~ 1 の範囲で、そのピクセルが影に遮られているかどうかを表します。
  • A_shadow = 0 のとき、そのピクセルは完全に影の中にあり、直接光は遮られます。
  • A_distance = 0 のとき、そのピクセルは光源から遠すぎるため、直接光は 0 まで減衰します。
  • どちらも 1 のとき、そのピクセルはその光源からの直接光を完全に受けています。

URP では、GetMainLight(shadowCoord) によってメインライト情報を取得できます。ここには光の方向、色、距離減衰、影の減衰が含まれています。

ここでの shadowCoord は、現在のピクセルがシャドウマップ上のどこに対応するかを表す座標です。URP はこの座標をもとに mainLight.shadowAttenuation を計算し、そのピクセルがどれだけ影の影響を受けるかを表します。

直接光に加えて、このコードでは環境光も加えています。

SampleSH(normalWS) は、現在のワールド空間法線方向に応じて球面調和関数による環境光をサンプリングします。環境光は、空やシーン内の間接反射から来る基礎的な明るさを表すもので、物体の背面が完全に黒くならないようにする役割があります。特定のライト 1 つの方向には依存せず、全体的に柔らかい照明を与えます。

したがって、最終色は次のように考えられます。

Cfinal = Cdirect + Cambient

環境光の部分は次のように表せます。

Cambient = Calbedo · CSH(N)

これらをまとめると、最終式は次のようになります。

Cfinal = Calbedo · Clight · max(0, N · L) · Adistance · Ashadow + Calbedo · CSH(N)

影の生成

ライティング計算だけでなく、より自然な見た目にするためには、物体が影を落とせる必要があります。ただし、影の生成をすべて自分で実装するのはかなり難しいです。幸い、URP はシャドウマップの生成とサンプリングをすでに用意してくれているため、Shader 側では ShadowCaster Pass を宣言するだけで、物体が影を落とせるようになります。

この Pass は通常の色を描画する Pass とは異なります。物体の色を出力するのではなく、ライトの視点から物体を一度描画し、その深度情報をシャドウマップへ書き込みます。その後、他の物体がライティング計算を行うとき、このシャドウマップを使って現在のピクセルが遮られているかどうかを判断できます。

主な設定の意味は次の通りです。

  • Tags { "LightMode" = "ShadowCaster" }：URP に、この Pass が影生成用であることを伝えます。URP はシャドウマップを描画するとき、この Pass を使用します。
  • ZWrite On：深度書き込みを有効にし、物体の深度をシャドウマップへ書き込みます。
  • ZTest LEqual：小さい、または等しい深度を通すテストを行い、正しい遮蔽関係を保ちます。
  • ColorMask 0：色の出力を無効にします。シャドウマップに必要なのは深度であり、色ではありません。
  • ShadowPassVertex：URP が用意している影生成用の頂点シェーダー関数です。
  • ShadowPassFragment：URP が用意している影生成用のフラグメントシェーダー関数です。
  • ShadowCasterPass.hlsl：URP が提供する影生成の実装で、影のバイアス、クリッピング、ライト種類ごとの処理などが含まれています。

注意点として、ShadowCaster Pass が解決するのは「この物体が影を落とせるかどうか」です。一方で「この物体が影を受け取れるかどうか」は、前述のライティング Pass 側で処理します。つまり、GetMainLight(shadowCoord) から mainLight.shadowAttenuation を取得し、その影減衰を直接光の結果に掛けることで影を受け取ります。

まとめ

この記事では、基礎的な Lit Shader を実装しました。内容としては、カラーテクスチャのサンプリング、法線マップ、基本的な Lambert ライティング、環境光、影の受け取り、影の生成といった機能を扱いました。

これらの機能があれば、基本的なマテリアル表示には十分使えます。ただし、これはあくまで簡略化したライティング Shader です。現在使っているのはベースカラーテクスチャと法線マップのみで、高光マップ、金属度マップ、粗さマップ、AO マップなど、より完全なマテリアル情報はまだ扱っていません。

また、Lambert ライティングモデルは拡散反射だけを計算するため、高光、反射、金属度、粗さといった表現は含まれていません。より現実に近い材質表現を行うには、この基礎の上に Blinn-Phong や PBR ライティングモデル（Physically Based Rendering、物理ベースレンダリング）を実装していく必要があります。
